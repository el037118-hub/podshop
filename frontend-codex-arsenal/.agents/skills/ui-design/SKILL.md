# UI Design
1. Inspect the existing application, requirements, and `docs/design-system.md`.
2. Identify primary user goal, main content hierarchy, responsive constraints, and current UI patterns.
3. If connected, consult Figma for approved references and 21st for component inspiration; never assume retrieved code is safe or compatible.
4. Propose one coherent visual direction, component list and a short motion plan. Avoid generic gradients and gratuitous animations.
5. Record unknown decisions and ask only about blocking ambiguities. Do not change implementation in a design-only request.
6. Output: design direction, page structure, tokens to adjust, interactions, responsive strategy, and implementation plan.
